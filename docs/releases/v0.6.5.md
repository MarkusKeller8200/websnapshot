# WebSnapshot v0.6.5 – Navigation, Dokument-Renamer und Einstellungen

**14. Oktober 2026**

## Navigation und Gestaltung
- Ein einziger, einklappbarer linker Menübaum statt gleichzeitiger horizontaler Register und Seitenleiste. Die Bereiche «Dashboard», «Websites verwalten», «Snapshot starten», «Snapshot-Verwaltung», «Änderungsvergleich», «Dokumente herunterladen», «Sitemap», «Job-Protokolle», «Einstellungen» und «Updates» sind klar getrennt.
- Alle Navigationsbuttons, Symbole und Labels linksbündig, einschliesslich innerer Streamlit-Textcontainer.
- Abgeschnittene Kopfzeile behoben: ausreichender Abstand nach oben und normale, lesbare Überschriften.
- Leichtere Seiten: nur die aktuell gewählte Ansicht wird gerendert.
- Tabellen mit inhaltssensitiven Pixelbreiten; Zahlen schmal, Texte und Links breit, sehr lange URLs und Fehlermeldungen mit einer Obergrenze. Bei zu wenig Platz bleibt horizontales Scrollen möglich.
- Snapshot-Archiv, Detailberichte, Fehler und Crawl-Qualität in «Snapshot-Verwaltung»; Start und Laufzeitüberwachung auf eigener Seite.

## Änderungsvergleich
- HTML-Textänderungen zwischen zwei Snapshots werden **direkt im Browser** in einer zweispaltigen, farblich hervorgehobenen Vorher-/Nachher-Ansicht dargestellt.
- Filter nach hinzugefügten, geänderten und fehlenden Seiten.
- Ein gesonderter HTML-Export bleibt optional, ist jedoch nicht Voraussetzung für die Vorschau.
- Hinweis: Gespeichert werden extrahierte Textinhalte, **nicht die ursprünglichen HTML-Seiten oder ihr pixelgenaues Layout**. Fehlende Seiten sind nicht automatisch gelöscht.
- Sicherheitsbehandlung: Übernommener Seitentext und Titel werden vor der HTML-Ausgabe maskiert.

## Dokument-Renamer
- Pro Website konfigurierbare Herkunft, z. B. `DSB` oder `SEKB` (1–16 alphanumerische Zeichen).
- Namensmuster: `YYYY_MM_DD_HERKUNFT_Dokumentenname.pdf`; Leerzeichen und Windows-ungeeignete Zeichen werden durch Unterstriche ersetzt.
- Grossschreibung wählbar: erster Buchstabe, jedes Wort oder vollständig gross.
- Alternativ weiterhin **Original-Dateiname** ohne Präfix oder Datum (mit nötiger Dateisystem-Bereinigung).
- Herkunft des Datums wird für jeden Download ermittelt: eingebettetes Änderungs- oder Erstellungsdatum von PDF/DOCX, dann HTTP-`Last-Modified`, zuletzt ersatzweise Download-Datum. Falls keine zuverlässigen Dokumentmetadaten vorliegen, wird das Ersatzdatum deutlich gekennzeichnet. `pypdf` ist nun eine Installationsabhängigkeit.
- Die Dokument-Dateinamen enthalten **keinen URL-Hash**. Namenskonflikte erhalten einen Zähler `_2`, `_3`, …; bestehende Dateien werden nicht überschrieben.
- SHA-256 bleibt intern in der Datenbank; ein erneuter Download derselben URL wird als neu, unverändert oder inhaltlich geändert protokolliert. Die Datenbank bewahrt den ursprünglichen Dateinamen, Datum, Datumsquelle und den SHA-256-Status auf.
- Suchfilter und selektive Sammelaktionen der v0.6.4 bleiben unverändert erhalten.

## Globale Einstellungen
- Neuer Menüpunkt **«Einstellungen»** für alle Websites zusammen: frei wählbares absolutes Download-Verzeichnis (auch Windows-Laufwerk/Netzwerkfreigabe), Standard-Ordnerstruktur, Standard-Besuchslimit und Sitemap-Tabellenhöhe.
- Die Einstellungen werden in SQLite gespeichert. Ein neues Download-Verzeichnis wird beim Speichern auf Schreibbarkeit geprüft; **bereits vorhandene Downloads werden nicht verschoben**.
- Website-spezifische Optionen wie Browsermodus und Herkunftskürzel bleiben beim jeweiligen Website-Profil.
- Snapshot-Ergebnisse und bisherige Dokumente werden durch das Upgrade nicht gelöscht.

## Qualitätssicherung
- Regressionstests für Datumsquellen, Dateinamen, SHA-256-Änderungserkennung, Benutzereinstellungen, Navigation und Tabellenbreiten.
- Code und Tests werden bei jeder Änderung durch GitHub Actions geprüft. Die Release-Automation erstellt den Versions-Tag und das Release erst nach erfolgreichem Testlauf.
- Ein visueller Windows-Integrationstest und die Prüfung echter, unterschiedlich aufgebauter PDF-/DOCX-Quelldateien auf Kundenwebsites sind weiterhin erforderlich.

## Update unter Windows

Erst laufende Crawls beenden, `.data/` sichern, Anwendung beenden und dann:

```cmd
cd /d S:\_ChatGTP\WebSnapshot\websnapshot
git pull
.venv313\Scripts\python.exe -m pip install -e ".[dev]"
```

Anwendung anschliessend neu starten. Der Browsermodus benötigt zusätzlich Chromium (`.venv313\Scripts\python.exe -m playwright install chromium`), falls noch nicht installiert.
