# WebSnapshot v0.6.8 – Unterbereiche von Websites gezielt erfassen

**14. Oktober 2026**

## Neue Bereichserfassung

WebSnapshot kann nun Websites ab einem ausgewählten URL-Pfad erfassen, ohne auf andere Bereiche derselben Domain auszuweichen. Bei einer vollständigen Domain als Startadresse bleibt das bisherige domainweite Verhalten erhalten.

Beispiel: Startseite **`https://www.zh.ch/de/bildung.html`**.

Die Bereichserfassung umfasst:
- die Startseite `/de/bildung.html`;
- die gleichnamige logische Pfadwurzel `/de/bildung`;
- darunterliegende Seiten wie `/de/bildung/schulen.html` oder `/de/bildung/schulen/volksschule.html`.

Sie schliesst etwa `/de/gesundheit.html`, `/de/bildungspolitik.html` und alle anderen Hosts aus. Das `.html`-Suffix der Startseite wird bei der Pfadabgrenzung berücksichtigt. Für zh.ch die **tatsächlich abrufbare Startadresse mit `.html`** verwenden; nicht jede Website beantwortet die Version ohne Endung direkt.

### Auswahl pro Website

Unter **Websites verwalten → Erfassungsbereich** stehen zur Verfügung:
- **Automatisch (Standard):** Website-Root `/` → ganze Domain; Unterseiten-Startadresse → nur Unterbereich.
- **Nur Startseite und darunterliegende Pfade:** Erzwingt Bereichserfassung.
- **Gesamte Domain:** Erlaubt Links im ganzen Host.

Die Einstellung wird pro Website in SQLite gespeichert, und die jeweils verwendete Auswahl wird beim Start im Hintergrundjob festgehalten.

### Sitemap, Links und Dokumente

- Domainweite XML-Sitemaps werden weiterhin als Quellen gelesen; in die Crawl-Warteschlange kommen aber nur URLs innerhalb des festgelegten Unterbereichs.
- HTML-/Browserlinks ausserhalb des Unterbereichs werden **vor dem Besuchslimit** aussortiert. Die Anzahl verworfener URL-Kandidaten wird im laufenden Job und später im Snapshot-Protokoll angezeigt.
- **Direkt von erlaubten Seiten verlinkte PDF- oder Word-Dateien** werden auch ausserhalb des HTML-Unterpfads in das Dokumentinventar übernommen, wenn sie auf demselben Host oder dem bereits unterstützten zugehörigen `docs.<domain>`-Host liegen. So bleiben Dokumente in gemeinsamen Ablagen wie `/content/dam/...` erhalten. Das bedeutet nicht, dass beliebige externe Websites gecrawlt werden dürfen.
- Dokumentlinks werden direkt beim Entdecken inventarisiert und beanspruchen keine HTML-Seitenbesuche. Sie werden erst beim anschliessenden Dokument-Metadatenlauf geprüft.

### Full / Delta und robots.txt

Ein **Full-Snapshot** ist erforderlich, wenn ein bisheriger domänenweiter Bestand auf Unterbereichserfassung umgestellt wird. WebSnapshot verhindert in diesem Fall einen Delta-Lauf, der sonst geerbte Seiten ausserhalb des Bereichs weiterführen würde.

Die allgemeinen URL-Sicherheitsvorkehrungen, bestehenden Crawl-Limits und robots.txt-Prüfungen bleiben aktiv. Ein Bereichsscan garantiert nicht, dass jeder denkbare Unterpfad gefunden wird: Er erfasst zugängliche Sitemaps und verlinkte URLs innerhalb der konfigurierten Grenzen.

## Tests

Regressionstests prüfen den logischen Pfad `/de/bildung.html`, die Erkennung echter Unterseiten gegenüber ähnlich benannten Nachbarpfaden, das Filtern einer domainweiten Sitemap, verlinkte PDF-Dateien in gemeinsamen Ablagen, die Datenbankmigration und den Full-/Delta-Schutz.

## Installation

Vor der Aktualisierung laufende Hintergrundjobs beenden, die Datenbank unter `.data` sichern und WebSnapshot schliessen.

```cmd
cd /d S:\_ChatGTP\WebSnapshot\websnapshot
git pull
.venv313\Scripts\python.exe -m pip install -e ".[dev]"
```

Danach `WebSnapshot.bat` starten. Linux-CI-Tests ersetzen keinen visuellen Windows-Integrationstest.
